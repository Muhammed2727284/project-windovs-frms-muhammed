# Учёт заказов кафе

Учебный проект: настольное приложение для небольшого кафе. Программа ведёт меню, принимает заказы по столам, отслеживает их статус и считает выручку за день.

## Технологии

- C#, **Windows Forms**
- **.NET Framework 4.7.2**
- Хранение данных: XML-файлы через `System.Xml.Serialization.XmlSerializer`. Это стандартная библиотека, без NuGet и сторонних пакетов.
- Среда разработки: Visual Studio. Все формы открываются в конструкторе.

## Возможности

1. **Меню кафе.** Список блюд (название, категория, цена), добавление, изменение и удаление.
2. **Заказы.** Номер стола, выбор блюд и количества. Итоговая сумма считается автоматически.
3. **Статусы заказа:** «Новый» → «Готовится» → «Готов» → «Оплачен». Статус можно поменять в любой момент.
4. **Заказы на главной странице.** Таблица всех заказов, фильтр по статусу и поиск по номеру стола. Их можно использовать вместе.
5. **Отчёт за день.** Количество заказов (всего и по каждому статусу) и выручка.
6. **Сохранение.** Все изменения сразу записываются в файлы и загружаются при следующем запуске.
7. **Вход и регистрация.** Пароли хранятся только в виде хэша с солью.
8. **Две роли:** администратор и сотрудник. Админ-панель видна только администратору.
9. **Единый «кофейный» дизайн** для всех окон (класс `Theme`).

## Как запустить

1. Открыть `Muhammed.slnx` в Visual Studio.
2. Нажать **F5**.
3. Войти администратором:

| Логин | Пароль |
|-------|--------|
| `admin` | `admin123` |

При первом запуске создаются стартовое меню из 7 блюд и администратор `admin` / `admin123`. Администратор создаётся, только если в программе ещё нет ни одного пользователя.

Данные лежат рядом с программой, в папке `bin\Debug\Data`:
- `menu.xml` — меню;
- `orders.xml` — заказы;
- `users.xml` — пользователи (логин, ФИО, роль, соль и хэш пароля).

Чтобы начать «с чистого листа», удалите эту папку.

## Роли и права

Новый пользователь, зарегистрированный через окно «Регистрация», получает роль «Сотрудник». Сделать его администратором может администратор в разделе «Админ-панель» → «Пользователи».

| Действие | Администратор | Сотрудник |
|----------|:-------------:|:---------:|
| Просмотр меню кафе | да | да |
| Создание и изменение заказа | да | да |
| Смена статуса заказа | да | да |
| Удаление заказа | да | нет |
| Блюда: добавить, изменить, удалить | да | нет |
| Отчёт по выручке | да | нет |
| Пользователи: смена роли, удаление | да | нет |

Ограничения в «Пользователях»: нельзя удалить самого себя и нельзя снять роль администратора с самого себя. Иначе в программе может не остаться ни одного администратора.

## Описание форм

**LoginForm, «Вход».** Открывается первой.
- Название кафе, поля «Логин» и «Пароль». Пароль скрыт, его можно показать галочкой «Показать пароль».
- «Войти» или клавиша Enter. Если логин или пароль неверный, появляется сообщение «Неверный логин или пароль».
- «Регистрация» открывает окно регистрации. После неё новый логин подставляется в поле «Логин».

**RegisterForm, «Регистрация».**
- Поля «ФИО», «Логин», «Пароль», «Повтор пароля».
- Проверки: все поля заполнены, в логине нет пробелов, логин не занят (без учёта регистра), пароль не короче 6 символов, пароли совпадают.
- Новый пользователь получает роль «Сотрудник».

**MainForm, главное окно.**
- Вверху название кафе, ФИО и роль вошедшего пользователя, кнопка «Выйти». «Выйти» возвращает к окну входа, крестик закрывает программу.
- Слева тёмное боковое меню: «Меню кафе», «Новый заказ», «Заказы», «Админ-панель» (только у администратора). Пункт открытой страницы подсвечен.
- Справа область, куда подставляется выбранная страница.

**OrdersPage, страница «Заказы».** Открывается по умолчанию.
- Кнопки «Новый заказ», «Открыть», «Удалить» (только у администратора).
- Блок «Поиск и фильтр»: выпадающий список статусов («Все» или конкретный статус), поле «Номер стола» (Enter = «Найти») и кнопки «Найти» и «Сбросить».
- Блок «Статус выбранного заказа»: выбор нового статуса и кнопка «Изменить статус». При выборе строки в списке сразу подставляется текущий статус заказа.
- Таблица заказов: номер, дата и время, стол, статус, сумма. Новые заказы сверху. Двойной клик открывает заказ.

Пункт бокового меню «Новый заказ» открывает эту страницу и сразу окно нового заказа.

**MenuViewPage, страница «Меню кафе».**
- Таблица блюд только для просмотра и фильтр по категории.

**AdminPage, страница «Админ-панель».**
- Три плитки: «Блюда» (MenuForm), «Пользователи» (UsersForm), «Отчёт по выручке» (ReportForm).

**MenuForm, «Блюда».**
- Таблица блюд, отсортированная по категории и названию.
- Кнопки «Добавить», «Изменить», «Удалить» (с подтверждением) и «Закрыть».

**UsersForm, «Пользователи».**
- Таблица: ФИО, логин, роль. Своя запись помечена «(вы)».
- Выбор роли и кнопка «Изменить роль», кнопка «Удалить» (с подтверждением), «Закрыть».

**DishEditForm, «Новое блюдо» / «Изменение блюда».**
- Поля «Название», «Категория» и «Цена».
- Категорию можно выбрать из уже существующих или вписать новую.

**OrderForm, «Новый заказ» / «Заказ №N».**
- Номер стола.
- Блок «Добавить блюдо в заказ»: блюдо и количество. Если блюдо уже есть в заказе, его количество увеличивается.
- Таблица позиций. Количество можно поправить прямо в ней.
- Кнопка «Убрать позицию» и строка «Итого», которая пересчитывается при каждом изменении.

**ReportForm, «Отчёт за день».**
- Выбор даты (по умолчанию сегодня).
- Всего заказов, сколько из них оплачено, выручка и количество заказов по каждому статусу.

## Проверка ввода

Все ошибки показываются через `MessageBox`, и данные при этом не сохраняются.

| Где | Что проверяется |
|-----|-----------------|
| Блюдо | Название не пустое и не повторяет другое блюдо. Категория не пустая. Цена — число больше 0 и не больше 100 000. Подходит и запятая, и точка. |
| Заказ | Номер стола больше 0. В заказе есть хотя бы одно блюдо. Количество — целое число от 1 до 99. |
| Поиск | Номер стола — число больше 0. |
| Вход | Логин и пароль не пустые. При ошибке — «Неверный логин или пароль» (не уточняем, что именно неверно). |
| Регистрация | Все поля заполнены, логин без пробелов и не занят, пароль не короче 6 символов, пароли совпадают. |
| Пользователи | Нельзя удалить себя и снять роль администратора с себя. |
| Удаление | Должна быть выбрана строка. Удаление нужно подтвердить «Да». |
| Файлы | Если XML-файл повреждён, программа сообщает об этом, сохраняет копию `*.bad` и продолжает работу. |

## Вопросы на защите

**Почему XmlSerializer?**
- Он входит в .NET Framework и не требует сторонних библиотек.
- Файл получается читаемым: его можно открыть в блокноте.
- Объект превращается в XML одной строкой кода.

Требования к классам: публичный конструктор без параметров и публичные свойства с `get; set;`.

**Как считается сумма заказа?**
- У позиции `OrderItem` есть свойство `Sum = Price × Quantity`.
- У заказа `Order` есть свойство `Total`, это сумма `Sum` всех позиций.

Оба свойства вычисляются на лету и помечены `[XmlIgnore]`: хранить их в файле не нужно.

**Что будет со старыми заказами, если изменить цену блюда в меню?**
Ничего. При добавлении в заказ название и цена блюда **копируются** в `OrderItem`. Заказ хранит цену на момент заказа, как настоящий чек.

**Как работает фильтр?**
- `OrderService.Filter(orders, status, table)` перебирает заказы и пропускает те, что не подходят.
- `status` и `table` имеют nullable-типы (`OrderStatus?`, `int?`). Значение `null` значит «не фильтровать».

Поэтому фильтр по статусу и поиск по столу работают как вместе, так и по отдельности.

**Как считается выручка?**
- `ReportService.BuildDailyReport(day)` берёт заказы, **созданные** в выбранный день.
- В выручку входят только заказы со статусом «Оплачен», потому что неоплаченный заказ — ещё не деньги.

**Как выдаются номера заказов и блюд?**
Самый большой существующий номер + 1 (методы `DataService.NextOrderId()` и `NextDishId()`).

**Почему DataService статический?**
Данные в программе одни на все окна. Статический класс даёт любой форме доступ к `DataService.Dishes` и `DataService.Orders` без передачи объектов между формами.

**Почему у формы заказа «Отмена» ничего не портит?**
`OrderForm` работает с **копией** списка позиций. В настоящий заказ изменения попадают только по кнопке «Сохранить заказ».

**Почему нельзя хранить пароль открытым текстом?**
Любой, кто откроет `users.xml` в блокноте, узнает пароли всех пользователей. Поэтому в файле лежит только **хэш**: результат функции SHA256, по которому пароль восстановить нельзя. При входе программа считает хэш введённого пароля и сравнивает его с сохранённым.

**Зачем соль?**
- Соль — 16 случайных байт, своих у каждого пользователя. Хэш считается от «соль + пароль».
- Без соли у одинаковых паролей одинаковые хэши, и простой пароль можно найти по готовой таблице хэшей.
- С солью хэши одинаковых паролей разные, а готовые таблицы бесполезны.
- Для соли используется `RNGCryptoServiceProvider`, а не `Random`: значения `Random` можно предсказать.

**Как форма узнаёт, кто вошёл?**
Через статический класс `CurrentUser`. После входа `LoginForm` вызывает `CurrentUser.SignIn(user)`. Любая форма проверяет `CurrentUser.IsAdmin`, например чтобы скрыть «Админ-панель» или кнопку «Удалить». «Выйти» вызывает `CurrentUser.SignOut()`.

**Как защищены окна администратора?**
Двойная проверка:
1. Сотрудник не видит кнопок, ведущих к этим окнам.
2. `MenuForm`, `ReportForm` и `UsersForm` при открытии (`OnLoad`) ещё раз проверяют `CurrentUser.IsAdmin` и закрываются, если вошёл не администратор.

**Как устроено главное окно?**
`MainForm` — рамка: верхняя панель, боковое меню и пустая панель `pnlContent`. Каждый раздел — отдельная страница-`UserControl` со своим `.Designer.cs`. При нажатии на пункт меню метод `ShowPage` удаляет старую страницу, кладёт новую в `pnlContent` и подсвечивает пункт. Новая страница каждый раз создаётся заново, поэтому всегда показывает свежие данные.

**Как сделан единый дизайн?**
Все цвета и шрифты собраны в статическом классе `UI/Theme.cs`. В конструкторе каждой формы после `InitializeComponent()` вызывается `Theme.ApplyToForm(this)`. Метод обходит все элементы: делает кнопки плоскими, с курсором-рукой и сменой цвета при наведении, оформляет таблицы. Чтобы поменять палитру, достаточно изменить цвета в одном файле. Файлы `.Designer.cs` при этом остаются обычными, и формы открываются в конструкторе VS. В самом конструкторе VS видны стандартные цвета, «кофейный» стиль — только в запущенной программе.

**Как сделаны скруглённые кнопки, иконки и цветные статусы без сторонних библиотек?**
Стандартные элементы WinForms умеют только прямоугольники, поэтому `Theme` подписывается на событие `Paint` и рисует сам через `System.Drawing`:
- кнопки, поля ввода и карточки — `GraphicsPath` со скруглёнными углами и сглаживанием (`SmoothingMode.AntiAlias`);
- иконки — символы шрифта **Segoe MDL2 Assets**, встроенного в Windows 10/11;
- статус заказа в таблице — цветная «таблетка» в событии `CellPainting`: «Новый» синий, «Готовится» янтарный, «Готов» зелёный, «Оплачен» серый;
- шапка окна входа — градиент (`LinearGradientBrush`);
- аватар — круг с инициалами пользователя.
